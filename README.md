## About This Template

This template provides a solid foundation for building Flutter apps with:

- **Clean Architecture**: Separation of concerns with repositories, BLoC pattern, and feature-based folder structure.
- **Authentication**: Firebase Auth integration with Google Sign-In and Apple Sign-In.
- **State Management**: BLoC for predictable state management.
- **Theming**: Dynamic theme switching.
- **Localization**: Ready for internationalization.
- **Testing**: Unit and widget tests setup.
- **CI/CD**: GitHub Actions for automated testing and analysis.

## Getting Started 🚀

This project contains 3 flavors:

- development
- staging
- production

To run the desired flavor either use the launch configuration in VSCode/Android Studio or use the following commands:

```sh
# Development
$ flutter run --flavor development --target lib/main_development.dart

# Staging
$ flutter run --flavor staging --target lib/main_staging.dart

# Production
$ flutter run --flavor production --target lib/main_production.dart
```

_\*Flutter Clean Architecture Template works on iOS, Android, Web, and Windows._

## Customization

To use this template for your project:

1. **Rename the App**: Run the `rename_app.ps1` script to update the package name, imports, and pubspec.yaml.
   - Usage: `.\rename_app.ps1 -NewName "your_new_app_name"`
2. **Update App Icons and Assets**: Replace icons in `android/app/src/main/res/` and `ios/Runner/Assets.xcassets/`, and assets in `assets/`.
3. **Customize Features**: 
   - Modify repositories in `packages/` for your API integrations.
   - Update BLoC cubits in `lib/*/cubit/` for state management.
   - Add new features following the structure: create folders under `lib/` with `cubit/`, `view/`, `widgets/`.
4. **Configure Firebase**: Update `lib/firebase_options.dart` and enable services in Firebase Console.
5. **Themes and Localization**: Edit themes in `lib/app/theme/`, and ARB files in `lib/l10n/arb/`.

## Firebase Configuration 🔥

This template includes Firebase integration for authentication, messaging, analytics, and optional Firestore CRUD operations.

### Setup Steps

1. **Create a Firebase Project**:
   - Go to [Firebase Console](https://console.firebase.google.com/).
   - Create a new project or use an existing one.

2. **Enable Services**:
   - **Authentication**: Enable Google Sign-In, Apple Sign-In, and other providers.
   - **Cloud Messaging**: For push notifications.
   - **Analytics**: For app analytics.
   - **Firestore**: For database operations (optional).

3. **Generate Firebase Options**:
   - Run `flutterfire configure` in your project root.
   - Select your project and platforms (Android, iOS, Web).
   - This updates `lib/firebase_options.dart`.

4. **Configure Environment-Specific Options** (Optional):
   - For multiple environments, create separate Firebase projects or use different apps within the same project.
   - Update `lib/firebase_config.dart` to load different options based on environment.

### Enabling/Disabling Firebase Services

Firebase services are modular and can be enabled/disabled in `lib/firebase_config.dart`:

```dart
await FirebaseConfig.initialize(
  environment: 'development',
  enableFirestore: true,  // Set to false to disable Firestore
  enableMessaging: true,  // Set to false to disable Messaging
);
```

### Using Firestore CRUD

If Firestore is enabled, access CRUD operations via `ServicesRepo`:

```dart
final servicesRepo = ServicesRepo(...);
final crud = servicesRepo.firebaseCrud;
if (crud != null) {
  // Create
  final result = await crud.createDocument(
    collection: 'users',
    docId: 'user123',
    data: {'name': 'John', 'age': 30},
  );

  // Read
  final readResult = await crud.readDocument(
    collection: 'users',
    docId: 'user123',
  );

  // Update
  await crud.updateDocument(
    collection: 'users',
    docId: 'user123',
    data: {'age': 31},
  );

  // Delete
  await crud.deleteDocument(
    collection: 'users',
    docId: 'user123',
  );

  // Query
  final queryResult = await crud.queryDocuments(
    collection: 'users',
    field: 'age',
    value: 30,
    operator: QueryOperator.greaterThan,
  );
}
```

### Firebase Security Rules

For Firestore, set up security rules in the Firebase Console to control access.

Example rules:
```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

## Deep Linking and App Links

This template supports deep linking for custom app URLs (e.g., `app://profile`) and app links for web URLs that open the app.

### Setup Steps

1. **Install Dependencies**: `uni_links` is already added to `pubspec.yaml`.

2. **Platform Configuration**:
   - **Android**: Intent filters are added in `android/app/src/main/AndroidManifest.xml` for schemes `app` and `https` with host `yourdomain.com`. Replace `yourdomain.com` with your domain.
   - **iOS**: Associated domains are added in `ios/Runner/Info.plist` for `applinks:yourdomain.com`. Replace with your domain and enable in Apple Developer Console.

3. **Firebase Dynamic Links (Optional)**:
   - For shortened links, use Firebase Dynamic Links.
   - Configure in Firebase Console and update `firebase_config.dart` to initialize.

4. **Handling Links**:
   - Links are parsed in `lib/utils/deep_link_service.dart`.
   - Navigation is handled in `lib/main/view/main_page.dart`.
   - Example routes: `app://profile` navigates to profile, `app://settings` to settings.

### Testing Deep Links

- **Android**: Use `adb shell am start -a android.intent.action.VIEW -d "app://profile"`.
- **iOS**: Use `xcrun simctl openurl booted "app://profile"`.
- **Web/App Links**: Test with `https://yourdomain.com/profile`.

## Working with Translations 🌐

This project relies on [flutter_localizations][flutter_localizations_link] and follows the [official internationalization guide for Flutter][internationalization_link].

### Adding Strings

1. To add a new localizable string, open the `app_en.arb` file at `lib/l10n/arb/app_en.arb`.

```arb
{
    "@@locale": "en",
    "counterAppBarTitle": "Counter",
    "@counterAppBarTitle": {
        "description": "Text shown in the AppBar of the Counter Page"
    }
}
```

2. Then add a new key/value and description

```arb
{
    "@@locale": "en",
    "counterAppBarTitle": "Counter",
    "@counterAppBarTitle": {
        "description": "Text shown in the AppBar of the Counter Page"
    },
    "helloWorld": "Hello World",
    "@helloWorld": {
        "description": "Hello World Text"
    }
}
```

3. Use the new string

```dart
import 'package:c_template_app/l10n/l10n.dart';

@override
Widget build(BuildContext context) {
  final l10n = context.l10n;
  return Text(l10n.helloWorld);
}
```

### Adding Supported Locales

Update the `CFBundleLocalizations` array in the `Info.plist` at `ios/Runner/Info.plist` to include the new locale.

```xml
    ...

    <key>CFBundleLocalizations</key>
	<array>
		<string>en</string>
		<string>es</string>
	</array>

    ...
```

### Adding Translations

1. For each supported locale, add a new ARB file in `lib/l10n/arb`.

```
├── l10n
│   ├── arb
│   │   ├── app_en.arb
│   │   └── app_es.arb
```

2. Add the translated strings to each `.arb` file:

`app_en.arb`

```arb
{
    "@@locale": "en",
    "counterAppBarTitle": "Counter",
    "@counterAppBarTitle": {
        "description": "Text shown in the AppBar of the Counter Page"
    }
}
```

`app_es.arb`

```arb
{
    "@@locale": "es",
    "counterAppBarTitle": "Contador",
    "@counterAppBarTitle": {
        "description": "Texto mostrado en la AppBar de la página del contador"
    }
}
```

### Generating Translations

To use the latest translations changes, you will need to generate them:

1. Generate localizations for the current project:

```sh
flutter gen-l10n --arb-dir="lib/l10n/arb"
```

Alternatively, run `flutter run` and code generation will take place automatically.
